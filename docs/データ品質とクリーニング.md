# データ品質とクリーニング設計

更新日: 2026-08-13

## 原則

`secondary_prices`、`financial_summaries`、`raw/`以下の取得データは変更しない。
検出結果は`price_quality_events`、モデル入力は`price_v2_cleaned`として別管理する。
補正前後の値、理由、処置、Cleaning Versionを残し、同じ入力から再生成できるようにする。

## 原因分析結果

### OHLC境界矛盾: 45行・38銘柄

| 分類 | 行数 | 原因の判断 |
|---|---:|---|
| 2022-05-17の同日集中 | 24 | 多数銘柄に同日発生したYahoo側バッチ/丸め異常と推定 |
| 浮動小数点の微差 | 9 | CloseがHigh/Lowを極小幅だけ超過 |
| 単発の境界不整合 | 11 | 古いYahoo OHLCの不整合 |
| 非正値OHLC | 1 | 8766の2003-08-15でHigh/Lowが0 |

元値は保持し、派生層では正値OHLCのHigh/LowをOpen/Closeを含む範囲へ拡張する。
非正値OHLCは推測補間せず、派生OHLCを欠損にする。クリーニング後のOHLC矛盾は0行である。

### 調整後終値・価格センチネル: 5,852行・2銘柄

| 銘柄 | 異常 | 行数 | 原因 |
|---|---|---:|---|
| 8303 | 非有限値 | 3,007 | 配当値が2億～2.4億として入り、調整係数がoverflow |
| 8303 | 負値 | 746 | 同じ調整係数が符号反転 |
| 8303 | Close比10倍超 | 985 | 正値でも10^23～10^33規模の不正値 |
| 8303 | 出来高0・10億円超 | 12 | 上場廃止/再上場間の55,320,000,000円センチネル |
| 8766 | 負値 | 1,102 | 2003～2005年の配当・株式分割スケール不整合 |

8303では2004-03-26などの配当が`222,000,000`、8766では株価1.57に対して配当6.67として
記録されている。負値、無限大、巨大正値が配当落ち日前後で切り替わるため、企業価値の急変ではなく
YahooのCorporate Action調整チェーンの破損と判断した。

これらはraw Closeで置換しない。配当込み近似と単純終値を混在させると期間リターンが不連続になるため、
`model_price`を欠損化し、学習・バックテストの起点/終点として不適格にする。

## クリーニング規則 price_clean_v1

1. 非有限または0以下の`adjusted_close`をモデル入力から除外する。
2. `adjusted_close / close`が0.001未満または10超の行を除外する。
3. 出来高0かつ価格10億円超のYahooセンチネルを除外する。
4. 正値OHLCのHigh/Low境界だけを派生層で拡張する。
5. 非正値OHLCと負の出来高は補間せず欠損化する。
6. 無効行または10暦日超の空白をまたがず、最新の連続有効区間だけで特徴量を計算する。
7. 同じCleaning Versionの監査イベントは再計算時に置換する。

現在、8303は再上場後の連続データが12か月未満なので、6M特徴量は利用できるが12Mと12-1 Momentumは
欠損になる。8766の異常は古い期間だけで、現在の12M特徴量には影響しない。

|---|---:|---:|
| 行数 | 2,892,158 | 2,892,158 |
| 全列Hash XOR | 3104616339403915842 | 3104616339403915842 |

実行コマンド:

```bash
asset-poc analyze-price-quality
asset-poc publish
```

公開Snapshotはraw調整後終値を`raw_adjusted_close`、モデル系列を`adjusted_close`として分離し、
`price_quality_events.parquet`に監査情報を保存する。

## `poc`フォルダの開発フォルダ化

PoCを越えてPoint-in-Time Dataset、バックテスト、学習モデルへ進むため、開発フォルダへ変更してよい。
ただし物理的な`poc`→`development`リネームは、次を同時に行う必要がある。

1. Streamlit、日次タスク、バックアップタスクを停止する。
2. DuckDBバックアップを作る。
3. フォルダをリネームする。
4. `.venv`を再作成する。console scriptのshebangが現在の`.../poc/.venv/bin/python`を保持するため。
5. `scripts/register-tasks.ps1`の`$PocPath`と文書内の絶対パスを更新する。
6. Windowsタスクを再登録する。
7. 全テスト、`asset-poc publish`、Streamlit表示、バックアップを確認する。

DB名や環境変数の`POC_`接頭辞は互換性のため当面維持できる。フォルダ移行はデータ品質実装とは別の
独立作業として行い、途中状態で定期タスクを動かさない。
