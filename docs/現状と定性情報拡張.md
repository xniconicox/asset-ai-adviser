# 現状実装と定性情報の扱い

## このPoCの実装概要

このリポジトリの実装は、過去の「理想設計書」ではなく、実際にコードで動く`Rule Rank`を中心に構成されています。実装上の核は以下です。

- `asset_poc/features.py`: 価格特徴量を生成
- `asset_poc/ranking.py`: 財務特徴量と最終順位を生成
- `asset_poc/qualitative.py`: 定性情報を集約して特徴量化
- `asset_poc/database.py`: DuckDBのスキーマとupsert設計

コード上のモデルは「学習済みのランキングモデル」ではなく、相対パーセンタイルと重み付きスコアを組み合わせたルールベース評価です。

## 1. 価格特徴量

`calculate_price_features()` では、株価の時系列から次を作ります。

- `return_1m`, `return_3m`, `return_6m`, `return_12m`
- `momentum_12_1`
- `volatility_20d`, `volatility_60d`
- `downside_volatility_60d`
- `max_drawdown_252d`
- `high_52w_distance`
- `average_volume_20d`, `average_turnover_20d`

そのうえで、各銘柄を全体と同じモデル群・業種内で相対順位化し、

- `momentum_score`
- `risk_score`
- `price_score`

を計算します。

実装上の重要な点は、`groupby("model_group")` と `groupby(["model_group","sector33_name"])` により、業種内の比較と全体比較をブレンドしていることです。

## 2. 財務特徴量

`calculate_fundamental_features()` は、決算サマリーと直近株価から次の指標を作ります。

- `per`, `pbr`, `roe`
- `equity_ratio`
- `operating_margin`
- `sales_yoy`, `operating_profit_yoy`, `eps_yoy`
- `forecast_eps_revision`
- `financial_completeness`

ここで重要なのは、同一銘柄内で比較可能な期間を選ぶ設計です。`current_period_type` と `current_period_end` を見て、年度・四半期の混在を避けており、欠損時には `None` として扱っています。

## 3. 最終ランキングの構造

`calculate_investment_ranks()` は、次のステップで最終スコアを計算します。

1. 価格特徴量から `momentum_score`, `risk_score` を取り込む
2. 財務特徴量から `valuation_score`, `quality_score`, `growth_score`, `earnings_score` を作る
3. 定性特徴量があれば `qualitative_score`, `qualitative_confidence` を加える
4. `confidence = 0.4 + 0.6 * financial_completeness` を求める
5. `raw_6m`, `raw_12m` に重みを乗じて基本スコアを作る
6. `score_6m`, `score_12m` を `base + qualitative adjustment` で補正する
7. 6M/12Mでランキングを付ける

重みはコード上の定数です。

```python
WEIGHTS_6M = {
    "valuation_score": 0.10,
    "quality_score": 0.10,
    "growth_score": 0.15,
    "earnings_score": 0.25,
    "momentum_score": 0.30,
    "risk_score": 0.10,
}

WEIGHTS_12M = {
    "valuation_score": 0.20,
    "quality_score": 0.20,
    "growth_score": 0.20,
    "earnings_score": 0.20,
    "momentum_score": 0.10,
    "risk_score": 0.10,
}
```

補正は以下です。

```python
qualitative_delta = qualitative_confidence * (qualitative_score - 50.0)
score_6m = base_6m + 0.10 * qualitative_delta
score_12m = base_12m + 0.08 * qualitative_delta
```

つまり、定性情報がない場合は補正0で、元の数値ランキングを維持します。

## 4. 定性情報の役割

定性情報は「投資判断の総合判断」そのものではなく、数値スコアに対する小さな補正器として扱われています。実装上は次の順序です。

```text
disclosure_texts
  -> qualitative_analyses
  -> qualitative_feature_snapshots
  -> calculate_investment_ranks()
```

`qualitative_score` は 0〜100 のスコア、`qualitative_confidence` は根拠の十分性を表します。前者が低いと補正が逆転する一方、補正の大きさ自体は小さく保たれています。

## 5. モデルの性質と限界

この設計の特徴は次の通りです。

- 明示的な重みがあり、説明しやすい
- 業種・モデル群の相対比較を組み込んでいる
- LLMは「値を上書き」せず、「補正因子を与える」役割に限定される
- 投資推奨や売買シグナルは出さない

一方で制約もあります。

- 過去の相対順位と因子重みが固定的
- バックテストがない限り、重みの妥当性は不明
- LLMの信頼度が高くても、原文の質が低いと補正が信頼できない
- 価格の長期トレンドや市場構造変化を十分に説明できない可能性がある

## 6. 無料データを増やす視点

無料で増やしやすい追加データは次の三つです。

### 6.1 古い株価チャートの補完

無料で比較的取りやすい候補:

- Yahoo Finance daily history
- Stooq (日本株・海外株の長期のOHLCデータ)
- Alpha Vantage（無料枠は小さめだが簡単）
- FRED / macro time series をインデックス・マクロ因子として追加

特に日本株では、長期の`adjusted close` を取りたい場合、Yahoo Finance の `period="max"` や `interval="1d"` が最も実用的です。古いデータを定期的に取得するなら、同じソースを `raw` として保存し、利用時に `source_tier` を分けて管理する設計が有効です。

### 6.2 企業開示のテキスト収集

- TDnet / EDINET の決算文書本文
- IR資料、事業説明会テキスト
- 上場会社発表のプレスリリース

これらは、LLMへの入力として使えるだけでなく、原文のテキストから `outlook_score`, `demand_score`, `profitability_score`, `risk_control_score`, `earnings_quality_score` を構築するための定性データ源になります。

### 6.3 マクロと市場因子

無料で増やしやすい観点:

- 日銀政策金利推移
- CPI / 物価指数
- 企業収益の業界別サマリー
- TOPIX / 日経平均 / 銘柄別リターン分布

これらは個別銘柄の評価に対して、相対比較のベンチマークや回帰時の市況因子として使えます。

## 7. 研究の観点

最新の研究で多く見られる方向性は次の通りです。

- 価格・ファンダメンタルを並列に扱うcross-sectional ranking
- industry-relative percentile normalization
- listwise / pairwise learning-to-rank で順位を学習
- LLMを直接の投資判断モデルにするより、構造化特徴量抽出器として使う
- 事後的な特徴量だけでなく、開示時点で利用可能だった情報に限定して評価するPoint-in-Time設計

このPoCは、これらの研究に沿って「特徴量抽出器 + ルール重み」の形に近い設計になっています。現時点では学習モデルではなく、再現性と説明可能性を優先した実装です。

### 7.1 LLM実データ接続の検証結果

2026-08-10のTDnet開示から10社・10業種を選び、決算短信を優先しつつ説明資料・予想修正を含む12文書を`gpt-5.4-nano`のStructured Outputsで構造化した。

- prompt: `qualitative_ja_v4`、schema: `qualitative_v2`
- 入出力: 168,317 input tokens / 8,981 output tokens
- 標準料金での概算: 0.044890米ドル（12文書合計）
- 保存根拠: 54件、空白正規化後の原文一致率100%
- 平均confidence: 0.5529
- 対象: 建設、小売、繊維、サービス、医薬品、非鉄金属、金属製品、精密機器、保険、情報・通信
- 最大順位改善: 楽天グループ6M +24位、ショーボンドHD 12M +26位
- 最大順位低下: ワコールHD 6M -3位、サワイGHD 12M -6位

根拠は保存前に原文照合し、不一致項目を除外する。`qualitative_confidence`はLLMの自己申告ではなく、`0.8 × 根拠一致率 × 5要素の充足率`で機械計算する。評価CSV/Excelには原文URL、根拠JSONと人手レビュー欄を保存する。現時点で原文一致は確認できたが、スコアの妥当性は人手レビュー未完了であり、重みの有効性を示すものではない。

## 8. 結論

このリポジトリの現状は、最終的な投資戦略モデルではなく、相対ランキングの検証基盤としてかなり整理されています。特に、`Rule Rank v5` の構造は「決定的に統合した財務レコード + 数値指標 + 原文検証済み定性補正 + 透明な説明可能性」を備えており、今後はPoint-in-Timeバックテストと学習モデル評価が最も重要な改善点です。

古い文書の理想設計を捨て、実装に合わせた現実的な説明に揃えることで、対象範囲と前提条件が明確になります。
