## 財務レコード採用規則

同一銘柄・開示日・期間種別の複数行は237グループあった。多くは単純重複ではなく、同日の
決算短信、業績予想修正、配当予想修正の併存である。`fundamental_v2_canonical`は次を行う。価格異常は`price_clean_v1`で別に処理する。

1. 銘柄、開示日、期間種別、対象期間末、会計年度末が同じ行を同一候補群とする。
2. 数値項目の充足度が最も高い行を基礎にする。
3. 同日内の各数値項目は、開示時刻・開示番号・取得時刻が後の非NULL値で補完する。
4. 最新実績と最新会社予想を分け、予想修正だけの行で実績値を失わないようにする。
5. 同率時も安定ソートし、API返却順に依存させない。

全22,501行をシャッフルした再計算でも、492社の特徴量が一致することを確認済みである。

## 主系統の評価定義

- 評価日: 各月の最終取引日
- 特徴量Cutoff: 評価日までに利用可能だった情報だけ
- リターン起点: 評価日の翌取引日
- 目的変数: 起点から6か月後・12か月後の将来リターン
- 価格: Yahoo `adjusted_close`
- 表記: Yahoo調整後終値ベースの総収益近似

決算イベント評価は開示翌取引日を起点にした別系統とし、月次評価と混在させない。
現在Universeを過去へ固定する生存者バイアスは、PoCの制約として明示する。

## 実装順

### 1. Point-in-Time Dataset Builder

- 月次評価カレンダーを生成する。
- 過去価格だけから各評価日時点の価格特徴量を再計算する。
- 評価日時点で開示済みの財務だけをcanonical化して特徴量化する。
- 6M/12M将来リターン、Cutoff日時、Dataset Version、ソースをParquetへ保存する。
- 欠損、外れ値、業種偏り、情報リークを検査する。

### 2. Rule Rankバックテスト

- `rule_rank_v5_price_cleaned`を固定Baselineとし、6M/12Mを別々に評価する。
- Spearman Rank IC、上位分位リターン、分位Spread、勝率を測る。
- Turnover、最大Drawdown、業種偏り、売買コスト感応度を測る。

### 3. 学習モデル

- まずRidge等の線形モデル、次に勾配Boosting等の非線形候補を比較する。
- ランダム分割は使わず、Walk-forwardで学習・検証・テストを分ける。
- 期間外評価でRule Rankを上回る場合だけ採用候補にする。
- 銘柄ごとの寄与は係数またはSHAP等で説明する。

### 4. 継続学習・画面・LLM

オンラインで自動的に重みを書き換えず、月次または四半期にChallengerを再学習し、
Championと同一期間で比較する。画面にはモデルVersion、評価日、主要指標、6M/12M順位、
寄与上位要因、データ不足とConfidenceを表示する。

LLM定性情報は履歴が少ない間は限定補正を維持し、人手評価と定性あり/なしのAblationで
増分効果を確認してから学習モデルの主特徴量への採用を判断する。
